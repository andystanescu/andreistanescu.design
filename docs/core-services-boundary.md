# Core categories and Services

Categories and their case-study assignments belong to Core. The optional Services extension associates one service record with an existing category; disabling a service preserves its content and does not change the category or its case-study assignments. Category deletion remains a separate, explicitly confirmed action.

The current application runs with Services enabled by default. Set `SERVICES_ADDON_ENABLED=false` before starting or building the application to exercise Core-only mode. In that mode the service routes and controls are unavailable, public navigation and the footer omit Services, and a new database does not create the `service_items` table. Existing service data is retained when the feature is disabled. A category with stored service data cannot be deleted while Services is disabled; re-enable it to review the consequences.

Content transfer offers Categories independently from Services. Category exports include names, descriptions, order, historical aliases and case-study assignments by slug. If a referenced case study is not yet present during import, the assignment is retained and applied when the study is imported or created. Services exports refer to the Core category by name rather than depending on the database's numeric IDs. Version 1 exports that include `configuration.categories` and `configuration.services` remain supported. A Core-only installation rejects an import containing service records rather than silently discarding them; import that file with Services enabled.

This is a runtime boundary inside the current application, not a separately packaged commercial Core distribution. The repository still contains Services source files and static imports. Insights has a separate runtime and data boundary described in `core-insights-boundary.md`, but neither add-on has been physically packaged. A future distribution needs a package/build boundary, standalone installation and upgrade tooling, dependency ownership, and end-to-end verification of supported deployment and transfer combinations. Existing SQLite databases must be backed up before upgrades or content imports.
